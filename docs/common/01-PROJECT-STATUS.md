If you set up a fresh machine for this project, don't assume `npm i -g @agentrhq/webcmd` alone is enough; check `cloakbrowser info` for `Installed: true` too.
- **On Windows, if `cloakbrowser install`'s extraction step fails with `spawnSync powershell ENOENT`**, your shell's `PATH` is missing `System32` — prepend it (`$env:PATH = "C:\Windows\System32\WindowsPowerShell\v1.0\;C:\Windows\System32;" + $env:PATH`) for that one command.
- **`src/webcmd/executor.ts`'s `execute()` now resolves webcmd's real `.js` entry point and runs it via `node` directly (no shell)** rather than `spawn('webcmd', ...)` — the latter throws `ENOENT` for globally-installed npm binaries on Windows, and the tempting `{ shell: true }` fix is a real command-injection risk on this specific code path. `execute()` also now generates its own `runId` (`crypto.randomUUID()`) rather than depending on webcmd's internal one, which is never exposed to stdout. See `02-DECISIONS.md` ADR-007 for the full record if this pattern needs to be reused elsewhere.
- **`.mcp.json` now exists at the repo root** (project-scoped, committed, no secrets) — registers Dodo's own `dodo-knowledge` MCP server (docs semantic search, no API key needed). Either agent gets it automatically on the next session start; a **session restart is required** for a newly-added project MCP server to connect (Claude Code shows an approval prompt on first use after restart — this is normal, not a bug). Useful right now for researching `docs/02-DODO-INTEGRATION.md`'s open questions without needing a real account.
